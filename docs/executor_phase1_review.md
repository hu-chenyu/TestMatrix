## 2. 关键技术决策清单

每条格式为：**决策** —— 为什么这么选（以及替代方案为何被否）。

### 2.1 执行模型

1. **批次级单进程，而非每用例一进程** —— 实测 pytest 冷启动固定开销 1.595 s/进程
   （与用例数无关），1180 条按"每用例一进程"仅启动就 31.4 分钟，是单进程全量的 27 倍；
   `case_type=chip`（硬件独占）保留单用例进程，作为**显式例外**而非默认路径。
2. **结果来源用 Allure 结果目录，行级解析只做实时进度展示** —— Allure 通路是既有实现
   且被全量测试覆盖，真实执行只是"换一个数据源喂给它"；行级文本随 `-q` 级别、终端宽度、
   颜色码变形状，拿它当结果来源迟早对不上账。
3. **`cwd` 保持项目根，隔离的是产物目录而不是工作目录** —— 把 `cwd` 换成批次目录会让
   `pytest.ini` 的 `testpaths`/`pythonpath=.` 失效、收集不到用例；`cwd` 由
   `env_manager.PROJECT_ROOT` 显式钉住，不依赖"调用方碰巧在对的目录"。
4. **环境变量按白名单构造并清空 `PYTEST_ADDOPTS`** —— 外部环境常注入 `--cov` 之类参数，
   残留会污染本次产物目录与判定结果，让"平台跑出来的数"取决于外部环境。

### 2.2 执行目标与数据

5. **`source_ref` 存"仓库相对路径[::函数名]"，空值语义固定为"该用例不可被 pytest
   执行"，禁止回落 `case_id`** —— 不存行号（改一行即漂移）、不只存 node id（函数改名
   即失效）；回落到 `case_id` 会让"没配执行目标"伪装成一次执行尝试。
6. **`source_ref` 列类型定稿 `String(512)`** —— 正常值不超 200 字符；MySQL 严格模式下
   `VARCHAR(512)` 能挡住异常超长输入，`Text` 会让错数据静默落库。**注意**：SQLite
   不实现长度约束，库层不拦，录入侧与执行侧的正则校验才是真正的闸。
7. **回填判定顺序 A → C → B** —— 档 A（描述/名称含 `.py` 路径）与档 C（api/模拟专用）
   判据会重叠，先判 C 会把唯一可真实执行的用例标成"专用"并留空。
8. **回填幂等靠 `UPDATE ... WHERE source_ref IS NULL`** —— 先查后写之间存在窗口，
   把条件放进 SQL 本身，重复运行与并发天然安全，人工补录过的值永不被冲掉。
9. **`validate_source_ref` 下沉 `src/common/source_ref.py`** —— `case_manager` 反向依赖
   `executors`，执行侧再 import 它就成循环导入；校验规则必须单一事实来源，
   否则会出现"录入侧放行、执行侧拒绝"的口径分叉。
10. **迁移读旧结构必须用真正的 `SELECT *`** —— 用 ORM `select(table)` 会按新元数据投影，
   迁移前库里没有那一列，直接 `no such column`：迁移脚本自己把自己挡在门外。

### 2.3 子进程与超时

11. **`Popen` 替代 `subprocess.run`** —— 超时清理需要子进程 pid，而 `run` 不返回它、
    `TimeoutExpired` 上也不带；拿不到 pid 就只能杀直接子进程，孙进程会继续写产物目录。
12. **杀进程树按平台分工**：Windows `taskkill /PID <pid> /T /F`；POSIX `start_new_session`
    + `killpg`（SIGTERM → 轮询宽限 2 s → SIGKILL）。清理结果作为**可读描述**写进错误消息
    ——"尝试过清理"和"确实清干净了"是两件事。
13. **三层超时**（批次 3600 s / 用例 300 s / 无响应 900 s）—— 单层超时无法区分
    "整批跑飞"与"某条用例挂死"；用例级越界事后按 allure 的 `stop-start` 判定。
14. **退出码只决定批次状态，单条用例结果一律以产物为准**，并加三条"不假绿"硬要求：
    校验 `len(case_results) > 0`、产物目录运行前清空、`unmatched` 计数必须为 0。
15. **结果词表保持下游四值（passed/failed/error/skipped），细分语义走新增字段** ——
    给 `result` 加 `internal_error`/`usage_error` 之类枚举会越过 `record_execution` 的校验，
    异常在批次级 `except` 里被吞掉后表现为**整批判 failed**；改用 `exit_code` +
    `exit_reason` + `error_message` 前缀承载细分。
16. **新增命令行参数必须插在 `--` 终止符之前** —— append 会让它落到终止符之后被当成
    第二个测试文件路径，pytest 报 `file or directory not found` 并以退出码 4 收场。

### 2.4 输出与报告

17. **解析收敛到 `output_parser` 单一模块** —— 三处各写一套正则必然给出三个答案；
    解析口径由单元测试钉死在一处。
18. **`parse_ok=False` 与"计数全零"严格区分** —— 把"没跑成功"记成"零失败"是这类
    解析器最贵的错；`no tests ran` 还要求同时命中耗时特征，否则崩溃现场的裸小节标题
    会被当成正常汇总行。
19. **Allure 桥接收敛进 `report_analyzer.bridge_results_dir` 并返回三态** ——
    执行器只该关心"什么时候桥接"，不该知道"怎么桥接"；三态（成功 / 无可桥接内容 /
    失败）是旁路能力必须能自陈的结果。
20. **桥接回落批次号必须确定性（`pytest-{case_id}`）** —— `defect_statistics.execution_id`
    有唯一约束且统计不做静默更新，每次生成新号会让每条用例每跑一次就插一行统计，
    把批次数/通过率趋势的口径撑坏；重复执行命中唯一约束**如实记为桥接失败**，
    没入库就说没入库。真实批次号关联在 Day51 接入。
21. **产物目录自动保留最近 N 次，而不是靠人工定期删** —— 目录隔离把"每用例一个目录"
    变常态；清理三条守卫各挡一种事故：跳过当前目录、跳过存活不足阈值的（并发运行中）、
    只删超出保留数的。

### 2.5 队列与状态

22. **批次状态机终态是吸收态，同态自环只对 pending/running 开放** —— 崩溃补偿重投后
    批次行已停在 running，重入必须合法；把 finished 重新置 running 永远不合法。
23. **进度回写用 SQL 层自增（`SET passed = passed + 1`）** —— 由数据库保证原子，
    通过率在同一条 UPDATE 里用 CASE 表达式算完并避开除零。
24. **ACK 前必须确认批次已落终态**（`state_confirmed=False` 时拒绝 ack）—— 否则
    "ack 了但状态没写"会同时丢掉任务与真相，在途条目应留给 requeue 走"至少一次"。
25. **心跳必须走独立线程、独立 Event** —— 主循环在同步执行批次的整段时间里拿不到
    控制权，只在用例之间刷新心跳的话，一批里有一条慢用例就会让心跳停摆，
    `requeue_stale` 会在它跑到一半时重投出去：**补偿机制自己制造了它本该防止的双跑**。
26. **requeue 陈旧判据优先看心跳、并加四道闸**（幂等 SETNX / 重投次数上界转死信 /
    先移出在途再入队 / 坏消息就地清理）—— 正常批次跑十几分钟早已超时阈值，
    只看 `started_at` 判陈旧等于复制一份并发双跑。
27. **claim 释放必须比对属主（compare-and-del），读不到属主时 fail-closed** ——
    误删的代价是当场拆掉别人的双跑防线；而 `requeue_stale` 判定属主死亡后的**接管**
    则要 fail-open（不动就掐断唯一能救回崩溃任务的路径），两个方向的取舍不同。
28. **claim 接管的属主失配按心跳判定而非直接跳过** —— `mark_in_flight` 在 claim 之前
    执行，被挡者会覆写状态 hash 的属主，失配恒成立；直接跳过会让崩溃恢复从
    心跳 TTL（60 s）退化到 claim TTL（3600 s）。

### 2.6 Web 侧与测试基建

29. **逐行输出单独开一条 SSE 通道，不并进结构化事件总线** —— 逐行输出频率高两个
    数量级且可丢弃，并进 1000 条容量的历史环会把 `case_finished` 挤出回放窗口。
30. **输出捕获开关必须在触发前打开、且默认关闭** —— 执行器在每条用例 `run_one` 开头
    决定"逐行读还是一次性读"，晚开一步先跑的用例输出就永久丢了；默认关闭是硬约束，
    否则既有 59 条执行器用例的 `Popen` 替身（只有 `communicate`）会集体变红。
31. **stdout/stderr 必须两个读线程** —— 只读 stdout 时，子进程往 stderr 写满即阻塞在
    写调用上，主线程永久阻塞直到超时；pytest 的进度行与失败堆栈恰好分属两个流。
32. **输出流必须有显式终帧 `output_end`，且终帧不带 id 行** —— 缺终帧会让已结束的批次
    陷入"连上→服务端关流→浏览器重连"的热循环；终帧带 id 会把客户端游标推到一个不存在
    的行号上，重连时那段真实输出被断点过滤永久丢弃。
33. **双模式切换只落在 `TM_EXECUTOR` 一个环境变量上** —— `get_executor(kind=None)` 与
    Web 触发（不带 `executor` 字段）都读它，写这一个变量即让所有后续触发（含队列
    worker 消费的批次）自动跟随，不必改动既有触发载荷语义。
34. **per-run 唯一 Allure 目录的修复放在项目根 conftest** —— conftest 的加载范围是
    "被收集路径的全部祖先目录"，真实子进程用例写在 `output/...` 下，`tests/conftest.py`
    根本不在它的祖先链上。两道闸：把生效 `--alluredir` 重定向到必然新建的目录
    （`is_dir()` 为假即不进 rmtree 分支）+ 运行时关闭 `clean_alluredir`。
35. **不重定向执行器已隔离的产物目录** —— 执行器为每条用例分配的都是唯一目录，
    再嵌一层会让桥接按原路径解析不到结果文件、**静默失效**（表现为"报告数对不上"）。
36. **展示层 clamp 不改数据** —— 通过率展示前收敛到 [0,100]（非有限数归 0），
    数据库里是什么就是什么：修数属于数据治理，不该由前端偷偷改。

## 3. 踩坑与教训

从 `PROJECT_CONTEXT.md` 第 7 章抽出与执行器/执行链路直接相关的条目，保留**结论级教训**：

| 坑 | 一句话教训 |
| --- | --- |
| 7.42 判据把平台写死 | 本地全绿 ≠ 跨平台正确；判据里出现平台分支时，必须用"两个平台都成立"的形式写，且守卫测试自身要先证伪 |
| 7.44 热修只覆盖故障的一半 | 修一个缺陷时要问"同一条路径上还有没有同族分支"，且它的测试不能是空转的 |
| 7.46 兜底钩子挂在 `stream_with_context` 上 | 兜底挂错位置等于没挂；变异脚本"追加"而非"替换"会造出假存活 |
| 7.48 迁移脚本读旧结构用新元数据投影 | 迁移的输入是**旧结构**，任何按新 schema 取列的方式都会把迁移自己挡在门外 |
| 7.50 直接 `import TestCase` 触发 `PytestCollectionWarning` | 引入测试数据模型会打破"0 warning"门禁，改用别名导入 |
| 7.52 严禁并发跑两个 pytest 进程 | 本项目存在共享产物目录（Allure）与真实子进程，并行会话会互相踩；Day53 之后由 per-run 目录 + 唯一标记逐步消除 |
| 7.53 契约废弃时既有用例同时"报错"和"假通过" | 改契约前先算清哪条断言会红、哪条会假绿 |
| 7.55 改字段名只做字符串替换 | 测试会假通过：断言的字符串仍在，语义已变 |
| 7.57 `case_type='chip'` 是历史命名化石 | 三方裁决保留不改：改名会连带一批既有断言，收益不抵风险 |
| 7.58 Windows 上 `os.kill(pid, 0)` 会真的杀进程 | 探活进程不要用信号 0；平台差异要显式处理 |
| 7.59 monkeypatch 模块级 `os.name` 安全，改替身**类**属性不安全 | 时间/平台替身的作用域要显式确认 |
| 7.60 Windows 时钟粒度约 15.6 ms | 微秒时间戳**不保证唯一**，唯一目录名必须叠加自增序号或 pid |
| 7.61 `Path.is_dir()` 内部会调 `stat()` | 给 `stat` 打补丁会从 `is_dir` 冒泡异常，测试要精确模拟"扫描与 stat 之间被删"的竞态 |
| 7.62 新增行的裸泛型注解被 mypy 增量门禁硬阻断 | 新代码一律写全泛型参数（`dict[str, object]`） |
| 7.63 Windows 上 mypy 输出反斜杠路径 | 用正斜杠正则过滤本地 mypy 输出会得到**假阴性**，必须先做分隔符归一化再与 diff 新增行求交 |
| 7.64 "顺手多查一次库"打破已收口的性能不变量 | 有回归用例按"SELECT 恒为 2 次"断言时，新增查询必须重新设计而不是改断言 |
| 7.65 崩溃场景不要走队列 FIFO | 会被场景间互相污染：直接压入在途 list |
| 7.66 心跳线程与主循环共用 stop_event 会让既有回归失效 | 独立心跳必须有自己的事件对象 |
| 7.67 fakeredis 不带 Lua 引擎 | "最稳的写法"在测试环境里可能根本不可用，替代方案要能跑在测试替身上 |
| 7.69 Windows 上重定向到文件的 `print()` 是块缓冲的 | 靠日志文件轮询判"进程是否启动"会永远等不到，需显式 flush 或换判据 |
| 7.70 让方法从"可能返回 False"变成"恒返回 True"会制造死代码 | 行为反转后必须连带清理调用方的分支，否则覆盖率门禁会如实报警 |
| 7.71 "修复后现有测试应仍全绿"要先验算 | 被修的那个行为可能正是某条断言的靶子 |
| 7.72 `--clean-alluredir` 的删除动作本身才是根因 | 失败签名（退出码 3）指向的是"有一个删除动作"，把动作去掉比把目录改对更彻底 |
| 7.73 新增 SSE 流时帧 id 形状必须两端同构 | 复用带默认参数的公共发帧函数时，要问"这个默认值是给谁用的"；回归测试要用**真实客户端会产生的值** |
| 7.74 流式接口的耗时断言必须把 body 消费包进计时窗口 | "看起来在测"和"实际在测"是两回事；验证测试有牙齿的最强证据是把被测文件退回修复前版本跑红 |

**四类反复出现的元教训**：

1. **假通过比失败更贵**：假绿（计数全零当全通过）、假隔离（以为隔离了其实没有）、
   假拦截（`id: live:5` 解析失败后全量回放却"测试全绿"）——发现手段只有一个：
   把修复回退/注入缺陷，确认测试真的会红。
2. **"看起来等价"是主要风险来源**：`--alluredir` 命令行覆盖 addopts、`run` 与 `Popen`、
   `str | list` 入参、心跳时间戳与 `started_at`——每处都要给出**能被观测的证据**再下结论。
3. **副作用边界要顺着失败控制流走一遍**：守卫放在哪一行不看语法正确，看"失败到底从哪个
   分支退出"；清理动作要问"并发运行的另一方会不会被我删掉"。
4. **行为变更先算既有断言**：哪条会红、哪条会假绿、哪条依赖的是即将被反转的语义，
   算完再动手（并保留"这条断言仍未删除、已按新语义适配"的证据）。

## 5. Phase-2 展望（Day59+）

Phase-1 解决的是"能不能真跑、跑完的数可不可信"；Phase-2 解决"跑得更快、更懂项目结构"：

1. **pytest 钩子进阶**：`pytest_collection_modifyitems` 定制收集顺序与标记透传，
   让平台侧的"分级调度"真正作用到收集阶段，而不是只在批次层面筛用例。
2. **平台专用 pytest 插件**：以 `pytest11` entry point 形式输出结构化结果与执行日志，
   把"解析终端文本"这条路降级为兼容兜底（文本形状脆弱是 Phase-1 已确认的约束）。
3. **xdist 并发执行**：批次内并行，前提是同批次产物目录隔离已经完成（Phase-1 已就位），
   并需要重新核算三层超时与进程树清理在"多 worker"下的语义。
4. **量化报告**：把执行器自身的指标（单用例耗时分布、冷启动开销占比、重投率、桥接
   成功率）做成可对比报表，用数据决定"下一批该优化哪一环"。
5. **结果归一**：真实/模拟双模式的结果字段统一归一，使看板与质量度量口径在两种模式下
   完全一致（当前差异已在 KNOWN_LIMITATIONS 中如实登记）。
